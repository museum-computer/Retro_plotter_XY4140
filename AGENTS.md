# AGENTS.md — правила работы в репозитории Plotter-XY 4140

Проект: автономная печать HPGL-рисунков с microSD на советском графопостроителе **XY 4140** через Arduino Nano. Ниже — контекст и жёсткие правила, которые нужно соблюдать, чтобы код оставался рабочим. Общее описание для человека — в `README.md`.

## Контекст в одном абзаце

`Arduino Nano` (ATmega328P, 5 В) управляет 6-контактным разъёмом XY 4140: PEN, STEP, X/Y, +/−, READY, GND. Шаг = 0,1 мм. Файл HPGL читается с microSD по SPI, разбирается инкрементальным парсером, кнопка D8 листает файлы, D9 останавливает печать, A0 мигает. Прошивка не выводит в Serial ничего: лог есть только в стендовом скетче.

## Жёсткие ограничения

1. **Никакого Serial в `xy4140_plotter.ino`.** Рабочая прошивка не пишет в порт, не мигает отладочно, не печатает имён файлов. Лог — только в `test_interface`.
2. **Текущий режим — самопроверка.** `SELFTEST_A 1` в `xy4140_plotter.ino`: при включении рисуется буква «A» и рамка поля, карта и кнопки не используются. Код чтения SD и кнопок остаётся в файле и включается константой 0, **не удалять**. Следствие для сборки: при `SELFTEST_A 1` компилятор выбрасывает ветку SD/парсера, поэтому проверку режима печати делать, временно ставя 0, иначе изменения в парсере не попадут в бинарник и останутся непроверенными.
3. **Никаких экранов, шрифтов и сетевого ввода.** Это автономное устройство с двумя кнопками. Требования заказчика: только рисунок, управление кнопкой следующего файла.
4. **Только 5 В TTL.** Ни преобразователей уровня, ни 3,3 В-сигналов, ни подтяжек к 3V3.
5. **Источники — только ASCII, без диакритики.** `.ino`, `.h`, `.cpp`, `.ps1`, `.plt`, `.properties` проверяются на байты > 127. Комментарии в коде — латиницей без диакритики, по-чешски без знаков, как уже принято в `XY4140.h`/`XY4140.cpp`. Русский текст допустим только в `README.md`, `AGENTS.md` и `docs\wiring.html`.
6. **Структура Arduino неприкосновенна.** Имя папки скетча = имя скетча, библиотека = `libraries\XY4140` с `library.properties` и `src\XY4140.h`, иначе Arduino IDE и CLI её не найдут.
7. **Внешние зависимости — только `SPI.h`, `SD.h`, `XY4140.h`.** Новые библиотеки не подключать.
8. **Память:** в режиме печати Flash занят на 47 %, свободно 1006 байт RAM. Нельзя вводить большие буферы, массивы строк на несколько рисунков, `String`. Только `char[]` фиксированного размера и `static`.
9. **Нет динамического выделения в коде скетча** (кроме внутреннего `File` из SD-библиотеки), файлы открываются и закрываются явно.
10. **Не переключать SD-библиотеку на классический API.** Код написан под новую (`File entry = root.openNextFile();`, `File::openNextFile(uint8_t)`). Возврат к `root.openNextFile(&file)` сломает компиляцию.
11. **Стандарт Arduino — AVR.** Ни `String`-утилит, ни C++17, ни динамических выделений: цель — `arduino:avr:nano:cpu=atmega328old`.

## Стиль кода

- Отступ 2 пробела, без табов, без `using namespace`.
- Именованные константы `#define` с прописными буквами подчёркиванием (`PIN_PEN`, `SPEED_US`), поля и статические переменные — с префиксом или строчные, как уже в файле; не вводить новые стили.
- Комментарии — короткие, по делу, на языке существующих комментариев (латиница без диакритики). Комментировать не очевидное (аппаратные странности, порядок handshake, почему вывод нельзя менять), а не очевидное.
- Один `#define` на параметр, который пользователь может крутить, с комментарием о единицах измерения.
- Публичные символы библиотеки — `XY4140_`/`XY4140`, методы — `_lowerCamelCase` с подчёркиванием для приватных, как сейчас в `XY4140`.

## Цикл сборки и проверки

Единственный инструмент сборки в этом окружении — `arduino-cli` по пути `C:\Program Files\Arduino CLI\arduino-cli.exe`. Полное дерево проекта работает как скетчбук, библиотека подключается флагом `--libraries`.

```powershell
$cli = "C:\Program Files\Arduino CLI\arduino-cli.exe"
$root = "C:\!GIT-PROJECTS\Plotter-XY 4140"
& $cli compile --fqbn arduino:avr:nano:cpu=atmega328old --libraries "$root\libraries" --warnings all "$root\xy4140_plotter"
& $cli compile --fqbn arduino:avr:nano:cpu=atmega328old --libraries "$root\libraries" --warnings all "$root\test_interface"
& $cli compile --fqbn arduino:avr:nano:cpu=atmega328old --libraries "$root\libraries" --warnings all "$root\test_wires"
```

Ожидаемые размеры, чтобы заметить регресс: `xy4140_plotter` ≈ 8604 байт Flash / ≈ 877 байт RAM при `SELFTEST_A 1` и ≈ 14620 / 1042 при `SELFTEST_A 0` (ветка SD выбрасывается), `test_interface` ≈ 7494 / 222, `test_wires` ≈ 7120 / 253. Предупреждения недопустимы — флаг `--warnings all` оставлен, потому что на AVR молчаливый `-Wunused` уже ловил баги.

Регенерация примеров:

```powershell

```

## Что проверять перед тем, как считать задачу выполненной

1. `arduino-cli` компилирует **оба** скетча с `--warnings all` без ошибок и предупреждений.
2. Все `.ino`, `.h`, `.cpp`, `.ps1`, `.plt` — чистый ASCII.
3. Если трогался генератор — он отработал, в `sd_card\` лежат 10 файлов, их содержимое начинается с `IN;PA;SP1;` и заканчивается `PU;SP0;`, координаты в пределах `10400 × 7400` HPGL-единиц.
4. Если трогался парсер — поведенческая проверка на всех десяти файлах: число перемещений больше нуля, «подъёмов пера» (PU) не меньше числа отдельных штрихов, ни одна координата не выходит за пределы, `clamp = 0`, `out = 0`. Проверять портом парсера на PowerShell в `%TEMP%\opencode\hpgl_parser_check.ps1`, а не глазами: этот порт повторяет состояние конечного автомата (`finishPair()` вызывается из `commitNumber()` и `startNumber()`, `finishCommand()` закрывает последнюю пару перед `;`).
5. Размер Flash и RAM не выросли заметно без причины.
6. В `README.md` совпадают числа и названия констант с кодом.

## Ловушки, на которые уже наступали

- **Потеря последней пары координат.** При `PU240,240;` старый парсер закрывал команду на `;` и не отдавал накопленную пару — все переезды отбрасывались, рисунок печатался из точки. Сейчас `;` только завершает команду, а координаты отдаются при закрытии пары и при завершении строки. Не «оптимизировать» это обратно.
- **Полилинии.** `PDx1,y1,x2,y2,…` — один приказ может содержать любое число пар. Ранняя версия принимала только две и рисовала неверно.
- **Регистронезависимость PowerShell.** `$h` и `$H` — одна переменная; `$h` в генераторе затирал высоту плато. Используются `$half`, `$H`, `$W`.
- **Ложный импульс на STEP при включении.** Уровни выводов задаются `digitalWrite` **до** `pinMode` в `XY4140::begin()` — иначе при подаче питания двигатель делает шаг. Этот порядок не менять.
- **Гонка с кнопкой STOP.** `loop()` не успевает опросить кнопку посреди длинной штриховки (одна линия `10_sweep.plt` идёт до 5 секунд), поэтому прерывание сделано через `setAbortHook()` — колбэк, который драйвер зовёт каждые 64 шага. `pumpParser()` один раз уже проверяет `stopRequested()`; сама кнопка читается в `service()` между проходами парсера. Убрать хук — значит вернуть неотзывчивый STOP.
- **READY — не просто чтение.** `isReady()` делает импульс LOW на D6, затем отпускает линию в HIGH и только потом читает D7. Упрощение до `digitalRead` ломает handshake.
- **Homing только по CART.** Концевик на X отсутствует, после homing X = 0. Бумага перед печатью должна стоять у левого упора. Не добавлять homing по X.
- **Согласование файлов.** `findNthFile()` дважды обходит каталог (счётчик, затем поиск по индексу). Считать, что порядок каталога стабилен между этими проходами, можно только потому, что `SD.begin()` вызывается один раз и файлы не меняются. Не вводить кэш имён — не хватит RAM.
- **Обратное движение молча пропадало.** `_stepAxis()` получала знаковое расстояние из `moveTo()` и выходила по `count <= 0`, то есть назад не уезжал никто. Это ломало и `+`/`-` в `test_wires`, и любой `moveTo()` вниз по Y сразу после homing, потому что после homing `_y` отрицательный. Теперь знак переносится в `forward`, счётчик берётся по модулю, а `_x`/`_y` уменьшаются при движении назад. По этой же причине из `home()` убран ручной `_y += _homeBackoff` — `AXIS_CART` его уже учитывает. Назад не «оптимизировать» в `if (count <= 0) return`.
- **Виртуальный ноль без движения.** `setPosition()` только записывает `_x`/`_y` и ничего не двигает. Нужен скетчу, который работает без homing: положение при включении неизвестно, а нулевой счётчик на краю поля не даёт уехать влево. В `test_wires` это виртуальное начало в центре поля плюс ограничение ±3 см.

## Аппаратные неизвестные — не «исправлять» наугад

**Снято замером на приборе, зафиксировано, версию увеличивать не из-за чего:**

- **Масса — контакт 2, а не 6.** Расхождение с таблицей `berk76` объясняется тем, что там нумерация со стороны разъёма компьютера, а считать приходится со стороны прибора. Записаны две гипотезы расстановки (A: 3=PEN, 4=STEP, 5=X/Y, 6=+/-, 7=READY; B: 1=PEN, 3=READY, 4=+/-, 5=X/Y, 6=STEP), версия не выбрана.
- **Все пять линий (1, 3, 4, 5, 6) в покое = 5 В постоянки.** Интерфейс 5 В TTL, Nano подключается напрямую. Прежние 8–9 В относились к шине доработанной платы 8051, а не к штатному интерфейсу.
- Контакт 7 не измерен.

Эти значения не проверены на живом приборе, потому что железа не было. Менять их только после замера, результат замера фиксировать в `README.md` и в комментарии константы:

- `MAX_X = 2600`, `MAX_Y = 1850` в `XY4140.h` против паспортных 2550 × 1800 шагов (255 × 180 мм).
- `DIR_INVERT` по умолчанию 0 — полярность направления на конкретном экземпляре неизвестна.
- `HOME_MAX = 4000` — заведомо больше длины оси Y, используется как предохранитель.
- `PEN_SETTLE = 10000` мкс, `USE_MAGNET = 1` — подобрано по опыту с магнитным прижимом пера, не по документации.
- `SWAP_AXES`/`X_FLIP`/`Y_FLIP` = 0 — рассчитано на собственные примеры генератора. Материалы 2018 года (185 × 261 мм) требуют `SWAP_AXES 1`, но их в репозитории нет, держать это в коде смысла мало.
- Направление счёта контактов разъёма (с какой стороны и по/против часовой стрелки считать 1…6) и маркировка контакта 1. Логическая раскладка 1 PEN, 2 STEP, 3 X/Y, 4 +/−, 5 READY, 6 GND подтверждена сторонним источником — `berk76/plottercontroller`, раздел 3.2.2; родное руководство (`docs\Plotter XY 4140.pdf`) её не содержит, про подключение говорит только «Anschlußkabel 536 648.1». Ориентацию счёта подтверждать замером на приборе и результат вписывать в `README.md`; в схеме и в коде порядок контактов не переставлять наугад.

Если задача требует значения, которое нельзя вывести из кода, — спросить, а не зашивать догадку в константу.

## Порядок работы над задачей

1. Прочитать `README.md`, затем целевые файлы целиком; не править по фрагментам.
2. Сформулировать, что именно сломано или не хватает, и проверить гипотезу в коде или в `docs\Plotter XY 4140.pdf` (текст извлекается через `pymupdf`; сам PDF как вложение прочитать нельзя).
3. Внести минимальное изменение в том же стиле, что и окружающий код.
4. Прогнать цикл проверки выше.
5. Не коммитить и не запушить без прямой просьбы пользователя.
